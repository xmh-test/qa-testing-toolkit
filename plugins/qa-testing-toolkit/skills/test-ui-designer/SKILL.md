# 从 UI 设计提取测试功能

把设计材料整理为测试设计输入，按需衔接同插件的常规用例生成、评审和 Excel 导出。用户明确的范围、格式和路径优先。

## 输入与范围

先区分静态设计、交互原型和待测实现。深入指定节点前，按 `references/source-reading.md` 先盘点所给设计材料中的全部平台与页面，再确定文件、版本、角色及本次范围。只有 UI 也可开始，不要求补齐 PRD；链接中的起始节点不是默认的完整范围。

- 按 `references/source-reading.md` 的对应分支读取 Figma 或 HTML。
- 总览记录平台、页面及纳入／排除／待确认和读取状态；限定范围、权限不足及未读项按来源读取规范处理。
- Figma 视觉读取与文件留存分开，默认不另存截图；具体留存授权及记录要求见 `references/source-reading.md`。
- 只有截图、局部权限或无法运行原型时，限定为可见证据，说明未读范围。无法识别任何有效设计内容时才请求可访问材料。
- HTML 若是待测实现，不能作为验证自身正确性的唯一设计基准。可以盘点现状，但验收目标需用户确认，不能宣称符合设计。

不执行待测程序、不输出执行通过率、实测缺陷或还原结论。读取或浏览设计原型用于理解材料，不等同程序验收。实际界面验证应另行进入执行流程，不自动扩大本技能范围。

## 功能提取

读取 `references/extraction-method.md`：

1. 建立平台/页面总览与证据清单；纳入项逐页读取布局、状态与交互，不能只读首个平台或首页。无法读取的项保留明确缺口。
2. 按页面入口、用户目标、操作反馈、数据约束、状态分支、对象影响六个维度提取。
3. 按独立验证目标或规则聚合 FP，不把每个控件机械变成一个功能点。
4. 每条规则标注“已明确 / 部分明确 / 待确认”。确定与未知内容分开，冲突不自行裁定。
5. 按同插件 `../test-case-generator/references/risk-design.md` 和 `../test-case-generator/references/extensions/index.md` 展开适用风险；在依据中记录上下文、扩展选择和逐 FP 风险处置。
6. 检查范围内页面/控件的归属：功能点、静态展示、装饰或未确认；不要求每个控件单独成例。

未知策略按 `../test-case-generator/references/confirmation-and-evidence.md` 合并为行为决策，提供选项并分批弹出独立问题。保存用户实际决定到项目记录后同步用例；已确定部分继续推进。候选识别不是终点，不能只把缺口写进文件而不处理影响核心用例的待确认问题。

## 交付与衔接

按 `references/ui_test_basis_template.md` 生成 `UI测试依据_${TIMESTAMP}.md`，保留二级章节和表头，无内容写“无”或 N/A。证据不足不补写虚构内容。

- 只要求提取/分析：只交付测试依据及缺口。
- 要求编写用例：以依据为输入，继续使用同插件 `test-case-generator`，读取其规则生成 V3 JSON 和总结，内部自检采用 `test-case-reviewer`。
- 要求 Excel：继续使用 `test-case-to-sheets`，不另建数据协议或导出实现。

沿用生成器的目录约定和同批时间戳，依据与用例保存到同一批次目录。更新保留原目录和有效编号，记录设计变化与受影响用例，不重编号无关内容。

REQ 表示“设计依据规则”，AC 表示可观察设计标准，不代表产品负责人已确认业务需求。V3 `metadata.source` 指向 UI 测试依据；依据和总结能追到原始节点/文件。证据状态放在依据中，不新增用例字段。

确定用例进入 V3 JSON；推导候选保存在依据第5节，包含条件、操作、拟验证结果和需确认假设，不混入 JSON 或 Excel，不计入确定用例数。规则明确但环境、样本或观察入口尚未准备的用例可以进入 JSON；在前置条件中标明具体准备事项，并在依据中按 case ID 列为“待准备”。没有任何确定用例时交付依据及候选，不生成空 JSON。

视觉检查可以编写用例，但标准用于未来执行，不能写成当前已验证事实。界面展示与功能行为分别标注，避免在一条用例中混合无关目标。

## 完成条件

- 按 `source-reading.md` 从范围总览反查每个纳入平台／页面的 FP、用例／候选或无独立目标说明，披露未读及未覆盖项。
- 按 `extraction-method.md` 检查功能意图、断言依据和证据状态；按风险规则核对异常、恢复及核心结果，准备缺口与规则候选分别记录。
- REQ／AC／FP／用例及原始来源可追溯；生成用例时完成其结构及语义检查。
- 交付说明设计完成范围、执行准备、未读内容及缺口，不将测试设计写成程序已执行通过。
