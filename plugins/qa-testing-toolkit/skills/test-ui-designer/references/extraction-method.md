# UI 测试功能提取方法

## 六个维度

| 维度 | 提取内容 | 不应推断 |
|---|---|---|
| 页面与入口 | 页面用途、可见入口、明确导航 | 未展示的页面不存在 |
| 用户目标 | 用户任务和目标对象 | 每个控件都是独立功能 |
| 操作与反馈 | 动作、明确展示的反馈和连线结果 | 点击一定成功、数据已保存 |
| 数据与约束 | 输入项、默认值、必填标记、明确规则 | 自设长度、唯一性、后端校验 |
| 状态与分支 | 空态、加载、成功、失败、禁用及触发依据 | 有错误态就知道触发条件 |
| 对象与影响 | 当前对象、可见变化、明确影响范围 | 批量影响、持久化、跨账号权限 |

## 聚合功能点

先写独立目标或规则，再关联页面、控件和路径。完成同一目标的连续操作可聚合；独立目标、不同结果分支、有独立流程的选择器分别记录。标题分类与 FP 不要求一一对应。

新建页有名称、源、目标、创建和取消时，可以提取任务创建、配置约束、取消新建；位置选择有独立浏览/选择/回填流程时再单独提取。这些功能可共用 `【新建与编辑】`，不拆成 `【新建/按钮/取消】`。

示例说明聚合方法，不证明实际产品具有相应规则。

## 证据状态

| 状态 | 标准 | 测试处理 |
|---|---|---|
| 已明确 | 画面、说明、连线或用户补充支持功能意图与结果，无未解决冲突 | 生成有证据边界的 AC 和行为或展示用例 |
| 部分明确 | 部分过程、触发条件或结果已知 | 保留可判定的功能目标；未知断言另列候选或缺口，不将整个功能退化成展示 |
| 待确认 | 依赖推测、存在冲突或未读到证据 | 保留条件、动作、拟验证结果和假设，确认前不作为确定用例 |

状态表示设计表达是否明确，不表示业务已批准或程序已实现。多个来源分别说明支持哪些事实。

来源按断言追溯：同一用例中的反馈、状态变化、持久化和权限要求可能来自不同证据。“原型明确”或“用户补充”标签不能代替节点、文件位置或可定位的确认记录。实现观察表示现状，不能独自证明应有行为。

没有原型连线不等于没有功能意图。可综合明确说明、同一对象的操作入口及前后状态稿建立行为依据，并写明各证据支持的事实。仅有按钮名、图层名或习惯性猜测时，仍只能作为推导。来源冲突时不选择对生成用例更方便的一方。

例：仅见“取消”按钮时，取消后返回何处、是否保留内容属于候选假设；不止记录“有取消按钮”，也不把候选结果写成已确认要求。

## 行为链路与执行准备

围绕用户目标组织“初始对象和状态 → 核心操作 → 即时反馈 → 终态及结果”。只写有依据的节点，不为凑链路编造加载文案、超时值或后台步骤。界面反馈、数据/资源状态、业务可用性按目标选择观察层次；界面成功提示不能独自证明持久化或业务可用。

前置条件只能准备本例需要的起点，不可把本例要验证的核心操作或成功结果预先设为成立。若本例专门验证成功态的展示，可以以前置成功态切入，但不能用它替代该功能的行为用例。

区分两类缺口：

- **规则缺口**：不知道应有结果、权限、影响范围或产品策略。已知部分继续设计，受影响断言保留候选并请求确认，不把多种互斥结果写进同一确定预期。
- **准备缺口**：规则和判据已知，但隔离数据、测试环境或观察入口尚未提供。仍可完成条件式功能用例，写清所需样本和观测能力，标记待准备；不得虚构现有页面/API，也不因无法立即执行而删除功能主线。

例如设计明确“归档后记录保留且可恢复”，可设计归档及恢复的对象、动作和结果；环境未提供记录只影响准备状态。保留期限未定义，则不生成到期删除的确定断言。

确定用例的准备状态与证据状态独立记录在依据中，按 case ID 对应。“已具备”仅表示所需条件已确认可获得，不表示已执行通过。候选是有用的风险设计，不算已覆盖需求；确认后再沿用追溯关系转入 JSON。

## 展开条件和归属检查

检查适用主流程、取消/返回分支、输入规则、状态变化、角色及平台差异。规则已知才做等价类和边界展开；有依据的上限 50 才能设计 49/50/51。

按 `../../test-case-generator/references/risk-design.md` 展开两类异常、恢复及适用架构风险。不要将全部异常一概降为候选：已有功能的对象归属、真实结果不被误报、数据不误伤等可判定质量目标可成为用例；自动回滚、互斥方式等未知专有策略才需确认。测试样本的数值可以构造并标注为样本，不能宣称是产品限制。观察窗口可以是执行方案，不等于产品 SLA；未执行时不报告实测结果。

控件清单关联 FP，或标记静态展示、装饰、未确认并说明理由。多个控件可映射同一 FP；不为装饰强造业务用例。

区分“界面展示”和“功能行为”。视觉用例可引用设计节点、明确尺寸和布局标准；不自设容差，不将浏览原型写成程序验收通过。

分类合并不等于删减风险分支。不同入口或平台若目标、条件、判据一致，可合并为分别执行的变体；取消、失败、恢复、依赖冲突等结果不同时保留独立分支，不因标题共用分类而压缩。
