# 测试计划

说明测什么、重点风险、如何组织执行及发布条件。更新时保留未涉及内容、真实来源和创建时间；用户指定的范围、格式和路径优先。

## 输入与基线

从当前需求及相关材料提取项目、需求名称与类型、业务基线、目标平台、影响范围、负责人、提测和上线时间。缺失信息标为待补充，不编造日期、人员、支持矩阵或业务规则。

客户端重构以已确认的变更为范围，未修改业务参考重构前正式版本；后端未声明变更时只规划兼容与必要回归。来源冲突列为待确认，不将当前实现自动作为预期。

## 组织内容

按功能跨度、平台与依赖、变更风险及协作需要选择详细度，不按篇幅或功能项数量划分规模。

| 内容 | 要求 |
| --- | --- |
| 目标与依据 | 明确验证目标、来源及有效版本 |
| 测试范围 | 区分本次测试、关联回归和不测范围；每项为功能名称及一句覆盖边界 |
| 重点测试项 | 对跨流程、状态、权限、数据及平台差异等实际高风险点说明风险和核验目标 |
| 用例编写指导 | 需多人协作或补充用例时，说明复用基线、适用设计方法和优先补充方向；规范引用同插件 `../test-case-generator/references/common_case_rules.md` |
| 策略与环境 | 说明执行方式及所需版本、平台、账号、设备、网络、数据、服务和观察能力 |
| 排期与分工 | 按已知日期、人数和设备资源安排；未知时只列阶段及依赖。用例数量仅在有基线或用户要求时估算并注明依据 |
| 上线标准 | 使用项目已确认门槛，说明失败、阻塞、跳过和延期的处理；缺少标准时提出待确认建议 |
| 风险与回滚 | 写不确定性、影响及处理；存在发布回退需求或高影响操作时，列触发条件、回退对象、数据保护、责任人和回退后冒烟范围 |

功能范围、风险重点、执行策略和待确认项各自表达其作用，不重复罗列同一内容。

## 发布门槛建议

项目未定义时，可建议关键用例全部完成且通过、高影响遗留缺陷处理完毕、其余遗留风险获发布确认、支持矩阵与恢复验证完成，并提供测试报告及发布建议。具体等级映射、比例及豁免须确认后才能作为正式门槛。

## 输出与检查

默认参考 [测试计划模板](references/test_plan_template.md)，按任务需要选择章节，保留功能边界和必要的用例指导。默认文件名为 `测试计划-{项目名称}-{需求名称}.md`；来源链接须真实可解析。

交付前核对范围与来源、重点与风险、排期与资源、发布标准及回滚条件的一致性。未知项有具体待确认问题，计划不展开成详细用例，不重复交付需求分析。
