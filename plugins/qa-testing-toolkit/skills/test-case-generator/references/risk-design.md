# 风险展开与实际结果核验

用于需求或UI已经表达的功能。先确定用户目标和实际能力，再选择会改变结果的代表风险；不按控件数量、分类数量或目标条数凑覆盖。

## 三种判断不要混为一谈

| 判断 | 处理 |
|---|---|
| 已有功能的通用质量目标，例如失败不能假报成功、结果属于正确对象、操作不能误伤无关数据 | 可以据已有功能设计正向和异常检查，注明由功能目标推导的判据，不必把每种故障都等待产品确认 |
| 产品专有策略，例如自动重试/回滚/级联删除、并发拒绝还是排队、离线缓存保留、版本选择 | 有来源才写确定预期；没有时保留完整候选并按功能归并提问 |
| 环境、样本或故障/只读观测渠道未准备 | 保留有判据的用例并标待准备，不将其误当成需求未知 |

缺少失败稿不等于不能设计异常；异常场景也不等于允许自行规定恢复策略。可以检查错误归属和真实结果不被误报，但不能顺带要求未知的重试按钮、错误文案或自动回滚。动作结果不确定时先设计核对当前事实，不臆定操作必定成功或失败。

## 每个功能点的展开

先覆盖“初始对象 → 操作 → 反馈 → 真实终态 → 后续使用”，再审视以下两类异常及恢复。每个FP在依据或总结的风险矩阵中给出用例、候选、具体缺口或不适用理由；复用已有代表用例，不为填表复制。

- **用户操作异常**：重复提交，取消后换对象，过期页面提交，处理中返回/关闭/重进，快速切换对象，前一操作结束后立即做下一项。按实际入口选择，不能默认确认框取消等于已接受任务取消。
- **系统或外部异常**：请求失败/响应丢失，成功响应但业务失败，旧响应晚到、重复事件，缺字段/未知状态，外部依赖不可达，资源不足，部分完成、记录与实际结果不一致。
- **恢复与数据保护**：错误是否归属正确对象，实际成功/失败/部分结果如何观察，原数据和其他对象是否安全，恢复后原入口能否继续使用。重试、补偿和清理仅在能力已明确时纳入确定断言。

按风险分级，不能因为属于异常就降级；也不要求每个展示FP都有所有异常。分类宽泛只限制标题归类，不减少有实质差异的条件、状态和结果分支。

故障注入与资源变更只作为设计步骤，不代表已获执行授权。需修改数据/资源或中断连接的用例追加 `destructive` 标签，并说明隔离范围、基线、获授权的准备方式和恢复/清理；不把同一段环境说明机械复制给纯展示用例。

## 从功能到具体场景的交叉检查

对会改变对象或数据的功能，用以下问题检查代表条件，而不是对所有维度做笛卡尔积。纯展示功能只选有意义的项。

| 维度 | 容易遗漏的条件 | 判断要点 |
|---|---|---|
| 操作时序 | 确认前被打断、受理后离开、重复提交、终态后立即下一操作、失败后重试、重进/重登 | 每个有实质不同结果或处理路径的条件有用例/候选/缺口；关页面不等于退出进程 |
| 初始与外部状态 | 对象不存在、已存在可复用、只存在部分资源、旧缓存与真实对象不符、另一授权操作者已修改/删除 | 正常全新起点不能代表所有已有/残留状态；外部变化的具体触发方式按实际能力选择 |
| 故障机制 | 输入/元数据类型错误、请求未受理、已受理丢回执、认证失效、资源限制、某路径失联、局部失败 | 按实际阶段/组件列具体故障样本与可观测结果；“有失败用例”不证明DNS、认证、容量等都已覆盖 |
| 恢复与后续 | 故障解除后新请求、旧错误晚到、恢复后的版本/数据/身份、原目标之外的对象 | 分开核对当前结果、原数据与非目标影响；不把恢复环境当产品自动修复能力 |
| 行为主体 | 当前账号/会话、同对象多入口、同设备其他对象、真实存在的其他用户/端/设备 | 不串对象与未授权不写入是通用目标；具体共享、互斥、角色和续跑策略另确认 |

先按风险选择不同机制的有效代表；相同目标/条件/判据合并复用，实质不同的故障样本不能仅用“分别模拟异常”一句掩盖。样本构造待准备不等于需求未知。宽分类、紧凑步骤和降低重复不应压缩有效风险。

反查缺口时分别标记：需求内可判定质量目标、需求内专有策略待确认、能力/适用范围待确认、明确范围外、已有覆盖/重复、来源冲突。前两类不能写成需求外；准备事项单独记录。没有正式PRD不影响已知功能的通用质量设计，也不授权猜测产品策略。

当最低判据已明确时，不得因同一风险还含未知策略而整条降为候选。已知异步读取不串对象/当前结果、数据显示不执行外部活动文本等，保留具体待准备的正式设计；只读渠道或故障/样本构造未提供是准备项。传输协议、刷新时限、自动恢复及输入转义方案等专有部分再列候选。只有功能/能力本身是否支持不明时才判范围待确认。

## 核心状态变更的核验层次

| 层次 | 设计问题 | 可用判据示例 |
|---|---|---|
| 界面反馈 | 用户知道正在处理或已经结束吗？ | 对应对象的即时反馈及终态，不固化未确认文案 |
| 对象与资源 | 改的是哪个对象，实际变化了吗？ | 身份、数量、版本、文件内容、进程启动记录或关联资源，与本次动作前基线对照 |
| 业务可用 | 用户目标是否真正达成？ | 访问对应服务、查询或保存后回读、取得目标文件；按功能选择 |
| 数据与影响范围 | 原数据及非目标对象怎样？ | 已确认保留/删除范围、配置、关联对象和样本恢复 |

核心功能应有匹配其用户目标的独立结果核验，至少一个行为用例覆盖从实际发起到该结果。展示用例和“成功后打开”用例可以另有目标，但不能代替核心变化的证据。重启后仍显示运行不证明发生过本次重启；保存提示不证明新值可回读；下载完成不证明文件内容属于本次对象。

按当前产品选择必要层次，不强迫所有操作做业务写入，也不把进程运行等同业务就绪。存在初始化任务时，按已知角色判定完成/运行，不能把所有退出状态都判故障。

跨模块核验绑定真实对象身份和本次动作，例如源对象ID ↔ 目标记录/资源 ↔ 实际结果，避免同名、旧缓存和历史成功被认作本次结果。没有可用入口时说明所需只读证据并标待准备，不发明面板、API或内部表名。只有当前功能明确由容器部署时，才考虑镜像构建、容器、网络/卷和实际服务；纯本地功能不强加此类检查。

## 按上下文选择扩展

使用 [场景扩展入口](extensions/index.md) 把产品、运行平台、架构和能力分开判断，再仅读匹配文档。此处保留通用方法，环境专项由扩展提供；扩展不会自动产生产品功能或固定阈值。适用项映射到现有FP风险矩阵，未知能力记范围缺口，未知策略保留候选，不为扩展另建强制产物或重复用例。

## 完成判断

覆盖检查从功能和来源向用例查遗漏，不能从现有用例反推完整。适用的两类异常没有用例/候选/具体缺口，或核心变更只检查Toast和状态标签时，覆盖自检未完成。有明确缺口可交付已知部分，但不得将该部分记为全面通过。条数、JSON结构和模板齐全均不能代替此判断。
