# 通用测试用例规则

## 独立与闭环

- 一条用例只验证一个核心测试点，用例之间不得存在执行依赖。
- 前置条件必须自包含并说明登录态、角色、配置、数据、网络、设备权限或外部服务依赖。
- 使用具体、可执行的数据；禁止 `{邮箱}`、`任意值`、`xxx`。易变对象使用“当前登录用户”“最新创建的订单”等动态描述。
- 新增、修改、删除数据时说明清理方式或隔离策略。

## 标题、步骤与预期

- 标题固定为 `【功能分类】【场景摘要】核心操作，预期结果`，20～60 字；两个标题分段必须使用中文全角方括号 `【】`，不得使用半角方括号 `[]`。
- `【功能分类】` 用于归类，是稳定、适度宽泛的子模块、页面区域或业务区域名称；同一区域的用例应复用同一分类，不按按钮、单次操作、字段、校验项或异常分支继续细分。例如，同一新建/编辑页面的创建、取消、必填校验和重名校验统一使用 `【新建与编辑】`。
- `【场景摘要】` 用于快速识别本条用例的关键条件、环境或业务场景，只保留最具区分度的信息。
- 规则说明中的“或”表示选择一种表达，不得在实际标题的 `【】` 中使用 `/` 拼接父子层级或罗列多个候选项。
- 方括号后的正文必须分别写明核心操作和预期结果，并使用中文逗号 `，` 分隔。
- 标题禁止使用“测试、验证、检查、确认、校验、正常、正确、合适”等空泛表达。
- 步骤从 1 开始连续编号，每步只执行一个动作，写明具体页面元素和输入值。
- 预期与步骤编号、数量一一对应；优先写 UI 可观测结果，有明确依据时补充 API、日志或业务状态。
- 异步结果必须写明等待时间和观察方式，不要求黑盒执行者验证不可观测内部状态。

## 覆盖与去重

- 覆盖基本流、备选流、异常流、权限、依赖缺失、合法/非法状态流转和关键链路节点。
- 主流程、关键链路、权限、支付/订单/审批状态和数据安全不得因去重被删除。
- 除非条件组合产生新业务规则，禁止字段、状态和平台之间做笛卡尔积。
- 核心字段完整覆盖等价类和边界；非核心字段同类错误保留 1～2 个代表场景。

## 优先级

- `P0`：核心主路径成功场景，失败会阻断发布。
- `P1`：显式需求、合法分支、常规异常和标准参数校验。
- `P2`：边界、极端值、错误容错、非法状态跳跃和低频健壮性。

## 平台与类型

- `directory` 固定为 `项目名|平台分类|模块名`；平台分类使用 `web`、`app`、`pc` 或 `all`。
- `functional_module` 必须是最高级业务模块名，并与 directory 第三段一致。
- `tags` 是非空数组，只允许 `web`、`mobile`、`desktop` 和末尾可选的 `destructive`；至少包含一个平台标记。
- 多平台步骤和预期一致时合并标记；存在实质差异时拆分用例。
- `case_type` 可使用 `功能用例`、`移动端用例`、`兼容性用例`、`性能用例`、`安全用例`，复合类型用 `|` 连接。
- Web 补充浏览器兼容、响应式和跨域；移动端补充手势、屏幕、生命周期、系统中断、弱网、推送、存储、缓存与无障碍；桌面端补充快捷键、多窗口、托盘和文件系统交互。
- 通用安全覆盖越权、注入、XSS 和敏感信息处理，但仅在产品形态适用时生成。
