# 功能点覆盖与追溯

为需求和验收标准建立稳定 REQ、AC 编号；为可独立验证的功能点建立 `FP-001`。沿用输入已有编号，不为凑覆盖率新增验收标准。

1. 按验收目标组织功能点，不按控件数量拆分。
2. 对每条已确认验收标准提供直接覆盖，必要连续操作可在一条用例中完成。
3. 基于已知规则扩展合法分支、异常、权限、状态、边界和平台差异。
4. 未知规则保留缺口；不适用维度标记 N/A 并说明原因。
5. 检查重复目标、无意义数据组合及遗漏的高风险分支。

每条用例填写 `functional_point_id`、非空 `requirement_ids`、`acceptance_criteria_ids`。来源位置及对应内容保存在总结追溯表，不能只列无法查证的编号。

ID 如 `TC-FP001-001`，与 FP 对应。新建按稳定顺序分配，更新保留已有 ID、新增追加、不回收删除编号。合并完全重复内容时记录被合并 ID。
