# 功能点设计策略

## 适用与输入

所有功能点都应用本策略。输入至少包含 FP、REQ、AC、角色、前置条件、操作、业务规则和可观测结果；缺失项进入需求缺口。

## 设计顺序

1. 为核心目标生成最短成功路径，核心阻断场景标记 P0。
2. 为每条验收标准生成至少一个直接覆盖场景。
3. 展开合法分支、常规异常、权限差异和依赖缺失。
4. 对有状态实体覆盖全部已知合法转换和关键非法跳跃。
5. 对关键业务链路生成节点级原子用例；不要把完整跨页面角色目标塞进单条常规用例，后续可由专项设计技能组合。
6. 应用平台专项和安全基线，然后执行去重。

## 追溯要求

- 每条用例必须填写 `functional_point_id`、`requirement_ids` 和 `acceptance_criteria_ids`。
- `design_methods` 至少包含 `functional-point`。
- 一个功能点产生多条用例时，按稳定设计顺序分配用例 ID：主路径、合法分支、异常、权限、依赖、状态、平台专项、健壮性。
