# 客户端与服务端协作场景扩展

适用于客户端与远端服务/设备协作，包括浏览器后端和NAS设备/云组合。先画出足够小的执行关系：发起端、实际执行者、数据归属、观察渠道与外部依赖；不知道请求主体时列问题，不固定协议或实现。

| 风险ID | 代表条件 | 可判定的核验目标 | 需要来源确认的部分 |
|---|---|---|---|
| CS-01 | 请求未到服务端、已受理但响应丢失、HTTP成功而业务失败 | 区分受理/终态，按真实对象核验，不从客户端超时推断服务端未执行 | 受理/任务标识、查询入口、补偿和重试；不发明API或强制任务中心 |
| CS-02 | DNS、连接超时/拒绝、认证失败、管理/业务/外部服务分别失联 | 指定实际路径的故障，错误归属与资源事实一致，非目标路径不被误判 | 代理、缓存、错误分类与提示文案；故障样本不是固定SLA |
| CS-03 | 旧进度晚于终态、重复通知、旧连接回执、重连后新结果 | 绑定目标/操作与会话，不倒退、不重复写、不将旧错误覆新成功 | 事件顺序/去重、历史重放、自动重连和持久化协议 |
| CS-04 | 同用户多入口/端重复写、其他授权操作者已更改/删除对象 | 不能静默改错对象或假报成功，结果和资源相符 | 锁/队列/合并/拒绝、幂等定义、冲突仲裁；按需读身份扩展 |
| CS-05 | 客户端离开/退出、服务短暂中断后重进 | 独立核对客户端显示和服务端真实状态，未确认意图不成为自动重放 | 谁持有任务、继续/暂停/终止、会话和历史恢复，不套统一续跑保证 |
| CS-06 | 批量或多阶段操作局部成功、资源不足、外部依赖失败 | 逐对象核对本次结果、残留和原数据，不以部分成功当整体完成 | 原子性、回滚、重试粒度、自动清理及人工恢复入口 |
| CS-07 | 配置更新、旧页面提交、跨服务数据暂不一致 | 当前动作采用何份配置/数据可追溯，观察真实终态和非目标影响 | 快照或执行时重读、一致性模型/刷新时限；不自定强一致或自动跨区求解 |
| CS-08 | 数据/资源已存在但业务尚未就绪；网络恢复后继续操作 | 本次版本/对象/数据与必要业务结果对应，恢复后新操作独立核验 | 必需/可选组件角色、就绪信号、业务健康检测；进程状态不是全部业务健康 |

把网络、客户端、服务端、外部依赖的失败分开取代表，不用“断网失败”一例覆盖所有。测试设计可要求准备只读证据，不自动授权调用生产API或注入故障。跨模块核验只服务当前用户目标，不扩大为依赖系统完整验收。

异步任务及结果读取已知时，旧读取/旧错误不覆盖当前对象的结果可正式设计；控制晚到响应的手段尚无则标待准备，不将整项误记为产品规则未知。是否存在WebSocket/轮询、自动重连或指定刷新时限不在该最低判据中，分别确认；不发明这些实现。
