# 场景扩展选择与使用

主技能负责通用测试设计、证据、粒度和交付。这里提供环境与能力的风险扩展，不替代PRD，不是固定用例库，也不新增技能入口或JSON字段。可由PRD、设计依据、用户说明或已知架构识别上下文；局部更新可沿用范围未变的记录。

## 先识别四类上下文

| 维度 | 需要确定的内容 |
|---|---|
| 产品/领域 | 本次目标、数据价值、设备或服务边界；如NAS，但不从名称推定所有硬件/协议能力 |
| 运行平台 | 已纳入的Web、手机、桌面客户端及实际载体；同一产品可以多端 |
| 架构/执行归属 | 纯本地、客户端与服务端协作、设备与云协作；谁发请求、执行任务、持有数据 |
| 能力/作用域 | 账号/会话、多个用户/端/设备、长任务、依赖/版本、配置与资源；已知、不适用、待确认分开 |

上下文有证据才写事实。用户明确范围优先；明显相关而尚不清楚的能力列待确认，不静默排除，也不强行纳入。无需为选择扩展先问完整问卷，已知部分继续。

这些维度可以叠加。例如NAS手机管理通常需NAS+移动，架构已知时再读C/S；身份和部署按实际能力追加。PC网页的平台扩展读Web，不因PC二字读桌面，但架构/身份扩展仍按事实追加。移动网页可选移动+Web，不机械套原生进程/系统权限。扩展重叠风险按同一对象、触发条件和判据合并，不能对所有平台/故障/用户做全组合。

## 将扩展变成有依据的场景

每个扩展按稳定风险ID列代表条件。只选择影响本次功能的项；一个ID可关联多个FP，同一个用例也可满足多个ID。扩展建议不是产品需求编号，不直接把ID写进 `requirement_ids`；用例仍追溯真实REQ/AC，通用判据在依据/总结注明“基于功能目标推导”。

在现有依据或总结的范围/风险节中记录下表，不另建强制文件；仅JSON交付时用随交付说明记录。

| 扩展/风险ID或未选项 | 选择依据与适用FP | 处理（用例/候选/范围待确认/不适用） | 对应ID或具体理由 |
|---|---|---|---|

- 已知功能的通用结果可判定：进入正式用例，准备不足标待准备。具体触发机制不同须有独立样本，不以笼统“各种网络异常”代替。
- 一项风险同时含通用目标和未知策略时，必须拆分处理，不把整项降为候选。例如已知异步读取的旧结果不能覆盖当前对象、外部文本不能作为活动代码执行，可以形成待准备用例；是否推送、如何注入旧响应、如何构造安全样本属于实际能力/执行准备的核对，不等于上述最低判据未知。自动重连、最后点击优先、缓冲行数、公式转义等专有选择才另列候选。只有能力本身未确认才标范围待确认，不能仅因工具/样本未提供就这样标注。
- 产品策略未知：通用判据与未知断言拆开；将策略存候选，按确认流程合并问题，不把整个风险丢到范围外。
- 能力是否存在/范围是否纳入未知：列范围待确认与影响，不能伪造入口；明确用户排除则写依据。
- 扩展与项目来源冲突：保留来源冲突，用户已确认规则优先，不为满足扩展覆盖改写产品决定。

评审从原始上下文和扩展风险反向查用例/候选/缺口，而非只看已生成用例。漏选明显适用扩展、所选项无处置、将未知策略当范围外，均属设计自检未完成；合理不适用不要求凑例数。只检查本次相关风险，不要求所有扩展ID都有一行。


项目特有配置和决定记录在项目依据；用户补充的场景文档按任务范围引用并注明来源，不作为额外执行或外发授权。
