# UI 测试功能提取方法

## 六个维度

| 维度 | 提取内容 | 不应推断 |
|---|---|---|
| 页面与入口 | 页面用途、可见入口、明确导航 | 未展示的页面不存在 |
| 用户目标 | 用户任务和目标对象 | 每个控件都是独立功能 |
| 操作与反馈 | 动作、明确展示的反馈和连线结果 | 点击一定成功、数据已保存 |
| 数据与约束 | 输入项、默认值、必填标记、明确规则 | 自设长度、唯一性、后端校验 |
| 状态与分支 | 空态、加载、成功、失败、禁用及触发依据 | 有错误态就知道触发条件 |
| 对象与影响 | 当前对象、可见变化、明确影响范围 | 批量影响、持久化、跨账号权限 |

## 聚合功能点

先写独立目标或规则，再关联页面、控件和路径。完成同一目标的连续操作可聚合；独立目标、不同结果分支、有独立流程的选择器分别记录。标题分类与 FP 不要求一一对应。

新建页有名称、源、目标、创建和取消时，可以提取任务创建、配置约束、取消新建；位置选择有独立浏览/选择/回填流程时再单独提取。这些功能可共用 `【新建与编辑】`，不拆成 `【新建/按钮/取消】`。

示例说明聚合方法，不证明实际产品具有相应规则。

## 证据状态

| 状态 | 标准 | 测试处理 |
|---|---|---|
| 已明确 | 画面、注释、连线或用户补充直接支持，无未解决冲突 | 生成有证据边界的 AC 和用例 |
| 部分明确 | 部分过程、触发条件或结果已知 | 拆出已知断言；剩余部分关联缺口 |
| 待确认 | 依赖推测、存在冲突或未读到证据 | 记录候选点，不生成确定性断言 |

状态表示设计表达是否明确，不表示业务已批准或程序已实现。多个来源分别说明支持哪些事实。

例：仅见“取消”按钮，可以设计展示检查；没有交互依据时，不断言返回列表、丢弃修改、不弹确认框。有错误态但无触发说明时，可记录视觉标准，不编造输入触发方式。

## 展开条件和归属检查

检查适用主流程、取消/返回分支、输入规则、状态变化、角色及平台差异。规则已知才做等价类和边界展开；有依据的上限 50 才能设计 49/50/51。

控件清单关联 FP，或标记静态展示、装饰、未确认并说明理由。多个控件可映射同一 FP；不为装饰强造业务用例。

区分“界面展示”和“功能行为”。视觉用例可引用设计节点、明确尺寸和布局标准；不自设容差，不将浏览原型写成程序验收通过。
