# DDT 数据驱动设计规范

## 纯 DDT 模板标题

- 纯 DDT JSON 模板标题不套用常规原子用例的中文全角方括号格式，使用“业务对象 + 数据分类/参数维度 + 校验目标或结果”的自然中文。
- 推荐示例：`登录账号按长度边界校验输入有效性`、`登录凭据按账号状态与密码组合判定认证结果`。
- 标题只概括数据设计维度与业务目标，不枚举每个 row 的输入值、成功/失败分支或提示文案；这些内容由 dataset rows 承载。
- 标题不得包含 `DDT`、case/dataset/row ID、`<参数占位符>`，或“等价类测试/边界值测试”等设计方法标签。
- dataset 无需新增标题字段；其关联 JSON 模板的 `title` 作为人工评审和 Excel 展示标题。
- BDD+DDT 模板按 BDD 场景标题规则命名，并与 Feature 的 Scenario Outline 标题逐字一致，不重复套用纯 DDT 标题公式。

## 适用范围

以下情况使用 DDT：字段校验、有效/无效等价类、已知边界、特殊值、格式差异，以及会产生新业务规则的条件组合。

- 已知边界按适用性考虑 `min-1`、`min`、`max`、`max+1`。
- 未知边界不得猜测具体数字，应记录为需求缺口。
- 非核心字段使用代表值，避免无意义的全排列。
- 行数据必须是具体值；分类名称不能代替输入值。
- 只有业务动作路径、状态转换和断言结构相同，且仅输入与对应预期变化时，才放入同一 dataset。
- 客户端校验、服务端业务拒绝、权限拒绝、网络失败等不同执行路径应拆分 dataset 或 Scenario Outline，不能通过一列 expected 混合。

## 组合规模与默认上限

生成数据行前，先计算独立参数维度的理论组合数：

`理论组合数 = 各参数候选值数量的乘积`

采用以下默认约束：

- 单个 dataset 建议不超过 5 个独立组合维度；超过时按业务规则、状态路径或风险域拆分，而不是继续增加维度。
- 理论组合数不超过 20，且每个组合都有明确业务意义时，才允许完整笛卡尔积。
- 理论组合数超过 20 时，禁止默认完整展开；优先使用等价类代表值、边界值、单因素变化、pairwise/正交组合和高风险定向组合。
- 单个 dataset 实际生成行数目标不超过 20 行；21～50 行必须逐组说明不可合并的覆盖理由。
- 单个 dataset 默认硬上限为 50 行。只有用户明确要求穷举、存在法规/协议一致性要求或有已确认的执行预算时才可突破，并必须在总结中说明原因和成本。
- 超限时按业务含义拆分 dataset，不得仅按“前 20 行、后 20 行”机械分片。

削减组合时必须保留：

- 每个参数的有效与无效等价类代表值；
- 已知边界的 `min-1`、`min`、`max`、`max+1` 中适用的值；
- 需求明确的高风险参数交互；
- 默认值、空值、特殊值以及历史缺陷组合；
- 每条业务规则至少一条正向和一条适用的负向数据。

输出总结必须记录参数维度、理论组合数、实际行数、采用的削减方法以及未展开组合的风险。不得为了满足行数限制而删除关键边界或业务规则。

## 一个 dataset 对应一条 JSON 模板

- 每个 dataset 只有一个 `case_id`，指向常规 JSON 中的一条 DDT 或 BDD+DDT 模板用例。
- 模板用例的 `ddt_dataset_ids` 包含该 dataset ID，`ddt_row_id` 固定为 null。
- row 不再关联不同的常规 JSON 用例，也不展开 JSON case。
- DDT 参数、分类、具体值和逐行预期以独立 DDT JSON 为权威来源。

## 参数与数据行

- `parameters` 说明参数名、类型、是否必填及适用的等价类/边界/特殊值。
- `rows[].row_id` 使用 `ROW-DDT-FP001-001-001` 格式并全局唯一。
- `classifications` 只允许：`valid-equivalence`、`invalid-equivalence`、`boundary`、`special`、`combination`。
- `values` 的 key 必须来自 parameters；值必须具体且可执行。
- `expected` 必须是该行可观察的明确结果，不依赖另一个 row。
- `priority` 只允许 P0、P1、P2。
- 每个 row 必须可独立执行，不能依赖上一行创建的数据、状态或执行结果。
- 数据行会创建或修改业务数据时，应定义唯一数据策略及行级或 dataset 级清理责任。

## JSON 模板步骤

- 纯 DDT 模板说明从指定 dataset 逐行取值执行，不使用 `{任意值}`、`xxx` 等无来源占位符。
- BDD+DDT 模板保存完整业务流程，并明确参数由关联 dataset 提供。
- 若一条数据行需要不同的业务路径，应拆为另一个 dataset 或 Scenario Outline，而不是把条件藏在 expected 中。
- 不因多个功能点使用相同字段，就将不同业务目标的数据组合到同一 dataset。

## 覆盖关系

每个 dataset 包含：

```json
"coverage": {
  "full_case_ids": ["TC-FP001-001"],
  "partial_case_ids": ["TC-FP001-002"],
  "execution_policy": "ddt-only-for-full"
}
```

- full 必须完整匹配平台、角色、前置、操作和全部断言。
- partial 仅说明有重叠，不能用于跳过常规用例。
- 两个数组不得重复，且只允许引用常规原子用例。
- BDD+DDT dataset 的 coverage 必须与 Feature 场景标签一致。

## 旧版兼容

读取旧 DDT V1 时允许 row 关联展开的 `case_id`，但任何新生成或重写的 DDT 均使用 V2 dataset 级 `case_id`，不继续扩展旧模型。
