# 飞书缺陷交接

默认只写本地 issues。仅用户明确要求提交远端时，才把已确认的产品缺陷交给同插件 [test-bug-submit](../../test-bug-submit/SKILL.md)。缺陷查重、补充或重开、上传和写后回读都遵循该技能；当前授权范围未包含的远端变更保持待处理。依赖或权限不足时保留本地交付。

- 使用 [缺陷模板](../assets/defect-template.md) 或项目既有本地格式整理实际步骤、预期依据、实际结果、影响、真实平台/构建、已知复现频率和脱敏证据。保留 run_id、case_id、来源计划/用例及执行实例链接；区分原生关联和文本引用。
- 提交前检查截图、日志与目标设备和步骤对应；未经允许不上传。工具或环境错误、测试代码错误及尚无充分依据的现象留在本地。
- 将交接结果、已有/新建 Bug ID、链接、回读状态和遗留原因写回本地问题记录。结果未知时不重新创建；同一问题在两种执行方式下复现时合并证据，不分别提交。飞书处理状态不改变测试结论，也不回写测试计划执行状态。
