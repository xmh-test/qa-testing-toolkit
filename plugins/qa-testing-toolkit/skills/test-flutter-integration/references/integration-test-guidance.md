# 集成测试与按需 MCP 指南

## 主要入口

优先复用项目验收启动能力，使用 IntegrationTestWidgetsFlutterBinding，再调用真实生产初始化流程。存储、依赖、服务、窗口和 Zone 均按项目能力初始化；不能仅挂载根 Widget 冒充完整客户端。外部配置缺失时给出明确原因。

读取项目工具链配置及 AGENTS.md。FVM、mise、Rust 等按仓库实际依赖使用，不将某个项目的工具链当成通用前置。示例命令须替换为实际入口和已连接设备；优先调用项目已有批次运行器。

单例模式或数据库锁导致应用实例冲突时，使用测试专用存储和独立进程，不清空用户真实客户端目录。测试数据有唯一归属，复跑不依赖旧轮残留。

## 前后置生命周期

- 用例独占的账号、文件、目录、权限和应用状态优先在测试内管理。通用夹具使用 `setUp`、`tearDown` 或 `addTearDown`。需要 `WidgetTester` 的步骤放在 `testWidgets` 中，通过初始化辅助函数与 `try/finally` 配对。
- 分配可识别的夹具 ID，及时登记清理，覆盖前置只完成一部分、断言失败和超时。清理应可安全重试，回读确认数据已清除或状态已恢复，保留原始测试错误与清理错误。
- 同一测试进程共享的资源可用 `setUpAll` 和 `tearDownAll`。跨批次、跨设备共享的临时账号或需要独立管理员会话的夹具，由运行器通过一个入口依次执行准备、业务用例和最终清理。管理员凭据单独注入维护入口，业务用例使用目标角色账号。维护步骤及结果独立记录。
- 安装、系统授权和前后台操作优先由可重放的宿主脚本完成，再由测试或运行器验证前置就绪。只有平台或工具要求人工操作时才交接，并记录原因与验证结果。

## 跳过用例

已知环境或夹具尚未就绪、且需要在本轮结果中显示为「跳过」的用例，保留原用例 ID 和框架注册。在对应测试代码中按目标平台声明跳过条件，写明具体缺少的条件，恢复条件具备后移除该声明。批次运行器仍将这些用例交给 Flutter。

`testWidgets` 的 `skip` 只接收布尔值。需要框架输出原因时，用支持字符串原因的 `group(skip: 原因)` 包住该用例，并保持完整测试名以用例 ID 开头。使用 `testWidgets(skip: true)` 时，在注册处的注释中标注原因。

```dart
group(
  caseId,
  () => testWidgets(caseTitle, runCase),
  skip: skipReason,
);
```

`skipReason` 在该平台需要跳过时为原因字符串，其余情况为 `null`。验证 Flutter 原生事件包含 `skipped: true`，报告保留可用的跳过原因。即使框架发出 `testStart` 注册事件，只要测试体没有运行，就记为 `started: false`。运行后才发现前置条件缺失的用例按实际证据记为「运行阻塞」。

## 等待和业务断言

- 以唯一 Key、类型与作用域组合定位；只有必要时补 Key，按代码改动规则记录。
- 普通动画可有界 pumpAndSettle；持续动画、网络和后台任务使用截止时间内的条件等待，失败输出最后检查点及实际状态。
- Toast 观察应在触发操作之前建立，触发后立即捕获。优先使用真实 Toast 组件/可观察事件，不覆写生产 Toast 使其永驻。预期文案来自确认依据；Toast 成功不等于任务或文件操作已成功。
- 异步复制、移动、下载：取得本例任务 ID，等待明确终态，再回读源/目标/实际内容。失败或超时先核实副作用；未确认任务停止时不删除其仍在使用的目录。无法观察终态则保留残留记录或标阻塞。
- 页面 pop 后等待路由退出或新的页面就绪，避免对离场动画中的旧页面重复点击。
- API 夹具及真实内容回读不替代被测 UI 动作。注入异常、模拟数据或模拟平台事件明确标注其验证范围。

## MCP：探索和失败定位时使用

| 场景 | Binding | Driver 开关 |
| --- | --- | --- |
| 独立 MCP Debug 探索 | Flutter Driver Binding | 原生 debug 中启用 |
| integration_test 正式执行 | IntegrationTestWidgetsFlutterBinding | 关闭 |

不要求每例先执行 MCP；已有稳定定位直接写测试和复跑。MCP 探索结果另行记录，不合并为正式测试通过。工具不可用时继续能独立执行的用例。

需要 MCP 扩展时复用已有 ENABLE_FLUTTER_DRIVER 入口。扩展须在普通 Binding 之前、与 runApp 同一初始化 Zone 中建立，仅限原生 debug；不要在测试入口重复建立 Driver Binding。编译期开关/依赖/Binding 变化后重启，普通 Key 变化按工具要求热重载或重启。

使用当前实例输出和实际工具签名连接。DTD 与 VM Service 是不同服务，不混用地址或旧端口令牌；需要 WebSocket 时用 VM Service 对应端点。确认应用和设备，不结束无关进程。

Driver 模拟文本输入不覆盖真实输入法、系统快捷键；系统权限和系统选择器按宿主辅助规则处理。持续动画确需关闭帧同步时记录原值，使用显式等待并恢复。发现异常先截图和保留日志，再清理/重启；MCP 无法截图时使用已有原生测试或宿主截图能力，记录来源和缺失原因。
