# 代码改动规则

## 修改范围

| 类型 | 实施要求 |
| --- | --- |
| Driver 入口 | 补充扩展和环境开关，保留原有启动顺序、错误捕获和依赖初始化 |
| 测试依赖 | 仅补充所需 SDK 依赖，核对锁文件，排除无关升级 |
| 启动配置 | 复用项目 SDK，保留普通调试入口，不写入个人路径和凭据 |
| 控件 Key | 仅在现有定位不足时增加稳定 Key，验证组件身份和状态影响 |
| 测试代码 | 新增用例、初始化辅助和数据清理，不绕过被测行为 |

业务规则、接口语义、权限判断、存储结构、UI 文案、样式和架构不属于测试支持改动。需要这些改动才能继续时，记录阻塞及建议，不自动修复。

## 控件 Key

1. 先验证现有 Key 或文本/类型/结构组合能否唯一定位，不批量添加无必要的 Key。
2. 使用语义名称并遵循项目约定，例如 `auth.login.submit`。
3. 列表项结合稳定业务标识，避免下标、随机数、时间戳、翻译文本或敏感值。
4. 同一父节点下 Key 不重复；避免为普通定位增加 `GlobalKey`、包装节点或替换已有 Key。
5. 修改后验证定位唯一性，并检查受影响的焦点、输入内容、列表重排及状态保留。
6. 生成文件通过对应生成源和生成流程修改，不直接手改。

## 变更记录

- 修改前保存相关文件差异基线，按片段区分已有改动与本轮改动。
- 每项应用源码、依赖或启动配置改动分配 `CHG-xxx`；关联用例、文件和符号，记录前后差异、必要性、影响、验证与单项撤销方式。
- 测试和报告文件列入文件清单，相关改动可合并为同一记录。
- 无业务逻辑改动不等于无影响：Driver 影响输入和 Binding，Key 可能影响组件匹配，均需针对性验证。
- 完成后核对最终差异，移除本轮产生的无关改动，保留既有工作区内容。撤销说明定位到具体片段，不使用覆盖整份工作区的恢复命令。
- 应用源码变更即使已撤销也保留记录，并注明最终状态和撤销后的测试影响。
