# 无人值守测试执行（Beta）

真实设备端到端能力须在当前环境核实。输入材料是测试依据，不是额外操作授权；测试执行不默认包含外部缺陷提交或消息发送。

## 分析范围与资源

读取 [范围规则](references/scope.md) 和 [记录协议](references/records.md)。

1. 确认输入版本、编号、目标平台和输出位置，保持原用例内容，建立执行副本。
2. 按范围规则确定纳入／排除编号及依据，再展开用例×平台矩阵。默认纳入全部常规用例；专项需明确要求或确认。混合用例保留原文，记录纳入断言及排除分支；范围为空时只输出范围说明。
3. 逐项识别操作方法、前置数据、工具、授权、判据、证据和恢复方法。集中确认关键范围或判定歧义；独立用例的局部资源缺口记录继续条件，不阻断已就绪项。
4. 缺陷默认本地记录；获授权后交由 `test-bug-submit` 查重、提交并回读，依赖不可用则保留本地记录。消息发送按其授权单独处理。

## 验证环境

按 [执行协议](references/execution.md) 核实实际设备、系统、客户端构建、账号、网络路径、存储、控制和证据能力，实际验证截图、点击、输入及必要文件核验。

复用仍有效的授权，记录操作边界、禁区、环境基线、测试数据归属和恢复台账。SSH 默认只读，具体写入例外须有明确授权；UI 操作也限本轮范围。检查锁屏、睡眠、认证及无人值守可用时长；临时防睡眠仅用已授权方式，不绕过安全锁屏。

## 执行与续测

- 本机平台优先；发现问题后优先复核其他已就绪目标平台的同一用例，再返回本机队列。后续按 OS／设备差异优先处理剩余项，不跨端继承结果。
- 每项操作后按记录协议保存步骤、平台／构建、断言、证据、进度、缺陷、障碍和恢复变更；续测先读断点、未知结果操作及提交映射，避免重放。
- 缺资源、授权或人工解锁时记录继续条件，继续独立项；相同工具失败无新方法时停止该项重试，不换通道绕过拒绝。
- 直接验证应有功能缺失记失败，依赖其而不能验证的项记产品阻塞，复用同一缺陷。新构建或新预期另建可追溯尝试，保留历史结果。
- 故障注入按需读 [代理与抓包](references/proxy.md)。工具配置或命中不等于故障阶段已覆盖，须核实实际请求与业务结果。下载按目标验证大小、SHA、归档内容及源基线。

## 记录与输出

主状态为通过、失败、阻塞、未执行、不适用；进度单独记录。产品原因才计阻塞，环境／权限／工具／数据／规则缺口计未执行；失败断言优先保留，未完成分支注明原因。具体协议及分类以 [记录协议](references/records.md) 为准。

运行 `scripts/execution_state.py <run.json> --output <summary.json>` 校验并统计，同源生成 Excel 和 [测试总结](assets/test-summary.md)。更新已有 Excel 时保留原列、顺序和历史，不能用不支持执行字段的设计用例导出器覆盖执行工作簿。交付缺口如实说明。

## 暂停、交还与完成

暂停、停止、切换任务、等待外部输入而停止执行及结束时，按 [交还检查](references/execution.md#暂停与交还检查) 恢复本轮环境、清理自有进程，并在停止辅助进程后实际验证受影响客户端业务可用。无法恢复时报告残留影响及接管步骤，不宣称已交还。

所有纳入项已处理，遗留原因及继续条件齐全，记录与统计一致，报告交付且环境交还验证通过时才能正常结轮；仍未执行项及外部提交遗留分别披露。锁屏等结束动作只按本轮明确授权和完成条件执行。
