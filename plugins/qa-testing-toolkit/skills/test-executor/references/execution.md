# 执行协议

## 关口产物

第一关产物：输入文件及指纹、需求口径、范围名称及组合规则、选择依据、纳入编号、常规/专项分类依据、专项启用授权、范围外清单、本轮纳入用例×平台矩阵、逐项能力/资源分析、输出位置和缺陷处理方式。每项资源写责任方、已有能力及验证结果、影响项、继续条件；可自行安装/准备的工具不直接转嫁用户。门禁状态为未核实/就绪/带局部缺口就绪，注明缺口不影响哪些项。

第二关产物：实际环境和构建、授权边界、工具烟测证据、运行条件、恢复基线。授权表记录来源、设备/账号、操作类型、资源范围、有效条件和外部目标，不储存密码。账户密码通过受控现有渠道使用，不写进报告/技能。启动前集中询问关键缺失信息，沿用现有有效授权。新增具体授权只影响相应项。

工具由当前会话发现并按其文档使用；Computer Use 为 UI 测试主路径。ADB 仅在明确允许时控制手机，SSH 默认只读。目的专用连接器用于日志或结果导出，不能以请求脚本冒充 UI 操作。观察到的合法写接口也不自动构成调用授权。

## 无人值守和调度

- 读取本机电源/锁屏状态与已有策略；支持时可创建临时保持唤醒进程（例如 macOS `caffeinate`），保存 PID 和期限，不修改永久设置。不依赖该机制避免安全锁屏；无法保证解锁的项提前列出。
- 手机指纹、系统认证、桌面锁屏不可绕过。发生时保存现场、安排其他平台；需要人工的项登记为未执行，进度保留。不把无人值守理解为永远等待用户。
- 初始队列为本机全部适用项；问题复核队列只插入其他目标平台中相关且已就绪的项。复核后返回原队列，已完成的跨平台项不在第二轮重复执行。
- 后续优先不同 OS/设备类型的平台，再处理同类浏览器版本。环境未确认的平台不能因优先级而自动启动。
- 工具失败有限重试：一次刷新状态后按事实修正；相同失败再现且无新方法时记录工具缺口，不无限循环或将其报为产品缺陷。

## 证据与断点

每次尝试记录时区时间、环境/构建、步骤、数据标记、真实结果、证据相对路径、必要请求关联和恢复动作。截图和日志要支持同一事件；仅凭相同文件名或完整大小不能证明文件正确。用独特数据/新文件和SHA排除旧缓存、同名旧下载和半成品。0字节文件也需核验真实响应和保存结果。

请求超时或丢回执后，先核查服务端/列表是否已生效，不重复创建或撤销。先记录即将进行的不可恢复操作和已授权精确目标，再执行并回读；操作结果不明时保留待核实状态。

文件/页面/应用版本改变后新建尝试快照，保留原版本结果，禁止拼接成同一构建通过。前端无固定版本时记录标题、观测时间、可得的资源指纹和变化说明。

## 环境恢复台账

每条包括变更前证据、目标对象、本轮变更、恢复方法、影响、授权引用、状态和恢复后证据。恢复状态为未改动/待恢复/已恢复/无法恢复。避免把保存恢复计划当成完成恢复。不要撤销用户在测试期间新增的无关变更；发现冲突先保留并记录。


## 暂停与交还检查

每次暂停/停止、等待外部输入而停止操作、切换任务或交还设备，按下列顺序执行；保存的断点是续测依据，不能依赖残留配置维持断点。

1. 保存用例进度、所用配置、拥有的进程/监听端口和后续重建步骤，停止新增测试变更。
2. 清空本轮故障注入，恢复受影响应用的代理开关、地址与本轮修改的证书设置；检查本轮触及的其他平台。只修改本轮变更，不覆盖用户期间新增的配置。
3. 复位本轮网络模拟、浏览器屏蔽/节流/缓存/保留日志、账号状态、端口转发与临时电源措施。以逐项基线核对为准，不以“关闭浏览器/工具”替代。
4. 原代理关闭时，确认客户端已不依赖测试入口，再停止自己的代理及其他辅助进程，并检查监听已释放。原代理为用户自己的长期服务时，恢复原路由，不停止用户服务。
5. 在辅助进程停止后，通过客户端 UI 核对连接状态，并实际进入/刷新一个正常业务页面（例如进入目录重新取得文件列表）。必要时用只读日志/请求辅助排除缓存，避免沿用停止前的结果。需要重新登录时使用本轮已授权账号，不保存新凭证、不修改密码。
6. 逐端记录配置复位证据、进程停止证据、停止后业务操作及结果；只有全部受影响客户端通过核验，才能记录 `handoff.state=verified` 并告知可正常使用。正常操作失败则记 `incomplete`，优先修复后重新验证；无法自行恢复则立即明确告知影响及最短人工恢复步骤。
7. 续测时先检查用户当前环境和授权，再按保存的方案重新建立测试配置；不能假定暂停前的代理仍运行或原参数仍适用。
