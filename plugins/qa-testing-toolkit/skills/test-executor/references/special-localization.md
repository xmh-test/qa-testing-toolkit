# 多语言支持专项执行参考

默认不启用。只有本轮明确纳入语言专项/语言矩阵后执行；常规用例已明确要求的单个语言文案断言仍按原范围验证，不自动扩展到所有语言或地区。

## 准备

确定正式支持的语言/地区、默认语言、切换入口和记忆范围、未支持语言回退、动态内容/错误信息及格式规则。缺少规则时集中列出判定缺口；不要自行认定法语等一定不支持，也不默认跟随OS、浏览器或账号。

形成语言×平台/构建×关键流程矩阵。记录原客户端语言、浏览器语言、OS地区、时区和输入方式；优先应用内切换，改系统/浏览器设置必须在授权范围并可恢复。使用有依据的术语表/产品文案核对，不把模型翻译当作产品标准。

## 执行与判定

- 语言切换：执行原用例规定的切换、刷新、重进、重登录及跨标签动作，核对实际文案和记忆范围。未确认持久化规则时记观察和规则缺口，不自行判错。
- 文案完整性：检查核心入口、对话框、错误、空状态、动态占位、数字与复数、变量插值。区分用户文件名/输入内容与产品界面语言；用户内容不应被擅自当作漏翻。
- 布局与输入：在真实已支持语言中核对截断、遮挡、换行、按钮可操作性，按已纳入范围测试长文本、非ASCII和组合字符。不自动加入未支持的RTL语言或伪本地化。
- 编码与产物：使用可追溯的多字节文件名/路径，验证复制、URL、目录和下载名称；下载内容按源SHA核对，乱码界面与错误解码文件分别记录。
- 地区格式与回退：按已确认规则检查日期、时间、时区、数字和单位，不因切换语言就推定地区格式也应改变；回退语言不明时不猜验收标准。
- 资源失败：先确认当前架构是否真的独立加载语言资源。仅在适用且明确纳入时注入资源失败，不为测试不存在的路径新增请求或把所有断网当作语言资源错误。

每条结果记录实际语言/地区、平台/构建、原始文案、预期依据、截图及必要请求/产物证据。同一缺陷可关联多种语言，但实际未验证的语言不得标记复现。

## 恢复

暂停或结束时恢复本轮修改的应用/浏览器/系统语言、地区、时区及缓存/故障设置；停止测试工具后核对客户端正常业务可用。语言规则未确认与工具缺口按未执行记录，不归为产品阻塞。
