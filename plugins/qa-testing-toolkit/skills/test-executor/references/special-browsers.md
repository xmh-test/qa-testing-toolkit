# 浏览器兼容性专项执行参考

默认不执行跨浏览器/版本专项矩阵。常规Web用例在本轮指定浏览器正常执行；不能因此自动增加Firefox、Safari、Edge或历史版本，也不能把一个Chrome结果外推全部浏览器。

## 确定矩阵和环境

明确桌面/移动OS、实际浏览器品牌及版本、引擎、普通/隐私模式和必需流程。用户只说“主流浏览器”时集中确认验收矩阵；已测版本如实记录。工具可自行准备时不直接要求用户代装，安装仍遵守当前授权及工具政策。

优先当前本机浏览器完成原步骤，再在差异平台/引擎执行已纳入项。同引擎不同品牌不能默认等价；设备模拟或修改UA不能冒充真实浏览器。需要跨OS浏览器但无对应设备时记录具体缺口。

记录浏览器版本、配置文件、扩展、下载策略、存储/缓存和调试设置的原状态。仅使用本轮拥有的标签/窗口，不能清空用户全部Cookie、下载或关闭用户页面。隐私窗口是否共享会话需实际核对，多开一个隐私窗口不一定是全新会话。

## 同步骤复现

| 目标 | 执行方法 | 判定限制 |
| --- | --- | --- |
| 页面与交互 | 同一需求基线、实际前端构建、数据和操作路径，检查布局、选择、导航与错误反馈 | 前端更新后分开记录，不能把不同构建的差异全归浏览器 |
| 会话与存储 | 按用例测试新会话、刷新、返回、重开、跨标签、授权及到期 | 记录缓存与实际校验请求，旧页面显示内容不代表服务器仍允许访问 |
| 下载与文件 | 实际点击下载，处理浏览器提示，核对唯一新产物、名称、大小、SHA及归档内容 | 提示“成功”、完整大小和同名旧文件均不足以证明正确 |
| 下载限制 | 用真实能限制本次操作的策略构造拒绝，再恢复后重试 | 禁用自动多文件不等于拒绝手动单文件；取消提示也不是策略阻止 |
| 网络失败与恢复 | 验证请求/流确实在所需阶段被中断，核查恢复与断点续传 | DevTools离线不一定作用于已移交下载管理器的流，必须有实际证据 |
| 字符与编码 | 使用原用例特殊字符/多字节数据，核验URL、页面与下载产物 | 不以浏览器显示的编码形式单独判定错误，核对最终目标和内容 |

跨浏览器缺陷按同一触发条件、预期与现象查重，逐项追加实际复现平台/版本；历史通过不得当作本轮已复核。浏览器自身限制与产品兼容性要求分开表述，未知支持策略先记规则缺口。

## 恢复与交还

恢复本轮修改的代理、站点下载设置、网络节流/阻断、缓存开关及保留日志等；仅删除/关闭本轮拥有且按授权可清理的资源。恢复客户端原代理后再停测试代理，停工具后重新进行正常页面访问及本轮改变设置影响的业务操作。认证或证书安全提示按工具规则交由用户处理，不绕过。
