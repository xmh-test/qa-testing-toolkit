# 代理抓包与注入

先确认所需阶段、实际请求路径、设备路由、工具授权及恢复基线。抓包工具错误不是产品错误。配置文件可能包含匹配标记，应使用测试数据、限制读取范围，不上传到缺陷或版本库；日志不保存认证头、Cookie、原始URL或载荷。

## Reqable 与客户端入口

用户已有 Reqable 时优先利用：用 Computer Use 读取实际版本和可用代理/断点能力，验证目标请求确实经过工具。依据当前工具说明选择转发、断点或重写；没有确认前不声称能精确断流。不开系统全局代理来代替已禁止的网络修改。

客户端具有开发者代理设置时，记录原开关、地址、证书放行设置。代理进程就绪后再按已授权范围设置客户端代理，先以合法只读请求验证正常转发及目标限制。手机上的127.0.0.1是手机本身，不是电脑；远程手机需要已授权的可达入口或端口转发。此 Python 工具仅监听电脑回环，不自行开放LAN监听。不自动安装证书、开启证书放行或ADB反向转发。

## Python HTTP 代理

标准库运行，不包含NAS、账号或业务码的默认值。示意命令中目标和路径必须替换为实际已确认值：

```sh
python3 scripts/http_fault_proxy.py --state-dir <本轮状态目录> serve \
  --target-host <目标主机> --target-port <目标HTTP端口> --port <本机端口> \
  --timeout 45 --max-body-bytes 16777216
python3 scripts/http_fault_proxy.py --state-dir <本轮状态目录> arm \
  --mode abort_before --method POST --path <已观察路径> --times 1
python3 scripts/http_fault_proxy.py --state-dir <本轮状态目录> clear
python3 scripts/http_fault_proxy.py --state-dir <本轮状态目录> status
```

`status`仅显示脱敏规则摘要，不证明进程存活或规则命中。使用独立状态目录；同一目录仅允许一个代理进程。规则使用次数持久化，重启不应重新执行已消耗的一次性故障。启动前清除旧规则，不能携带上轮注入启动业务。

| 模式 | 实际含义与判据 |
| --- | --- |
| abort_before | 不联系上游，日志 aborted_before_upstream；用列表/日志补核查无副作用 |
| drop_response | 上游响应完整读取后丢回执；用上游实际业务码和重新进入后的状态证明已受理 |
| delay_response | 收到上游响应头（JSON还完整读取）后延迟，不是请求前延迟；需UI与请求时序证明旧响应覆盖 |
| mock_json | 不联系上游，返回指定JSON；仅验证客户端对模拟业务响应处理，不证明真实后端返回同样错误 |

`arm`另支持 `--when-code`（实际观察的业务码）、`--delay`（0–60秒）、`--query-file`（键/字符串值精确匹配）、`--body-contains`（测试数据标记）、`--response-file`和`--http-status`。规则替换而非追加，默认命中一次。匹配配置与运行日志分离；规则文件不存认证凭证。日志以请求ID、规则ID、路径哈希和阶段关联，可在本地用预先记录的路径计算哈希核对。

边界：仅普通HTTP、单一批准目标；不支持CONNECT/TLS解密、chunked请求体、WebSocket或精确截断已有HTTPS下载；二进制响应正常转发采用流式读取。丢回执不是下载到某字节切断。云端下载不经过该HTTP管理代理时必须登记能力缺口。

暂停、交还或结束时按 [交还检查](execution.md#暂停与交还检查) 恢复客户端代理后停止辅助进程，并验证业务可用。

若代理已停、客户端无法登录且设置仅登录后可见，可在既有授权目标和原端口临时启动无故障转发，正常登录后从UI恢复代理配置，然后停止临时进程，再次验证客户端正常使用。不能猜改应用配置文件、扩大网络暴露或为方便永久保留代理。无法恢复时明确报告当前依赖、影响及接管步骤，不无提示交还。
