# 执行测试用例的范围规则

本规则用于选择已有用例，不替代用例设计或授予新的操作权限。在第一关确定本轮范围后，再分析资源和准备环境。

## 三个维度

- 范围集合：冒烟、功能、回归、兼容性、其他专项或指定编号。允许同一用例拥有多种标签，不能把case_type当作必须互斥的枚举；已有类型/标签只作选择依据，不重写源数据。
- 平台矩阵：OS、设备类型、浏览器及版本等运行条件。常规用例在Android上运行仍是常规功能测试，不自动启用移动系统专项。兼容性矩阵也不自动包含所有系统或版本。
- 优先级：默认决定执行顺序；仅用户明确说“只执行P0/P1”等时才过滤范围。P0不必然是冒烟，P2也可能在已确认的冒烟集合内。

## 集合定义

| 范围 | 纳入依据 | 未明确时怎么处理 |
| --- | --- | --- |
| 冒烟 | 已有冒烟标签、已确认清单中的核心业务链路 | 查找现有清单；没有则提出候选编号、链路和选择理由，确认后执行，不自行将所有高优先级用例纳入 |
| 功能 | 指定模块的正常、异常、边界、权限及状态变化功能用例 | 默认本轮输入的全部常规功能用例，不包含独立专项；原有功能断言照常执行，不因涉及编码或特定平台就误排除 |
| 兼容性 | 兼容性用例，以及明确要求跨环境复核的业务用例 | 明确兼容对象、品牌/版本矩阵与业务清单；不能只因某平台可用便自行扩展。缺少关键矩阵在第一关确认 |
| 回归 | 已确认的缺陷复测清单和变更影响范围 | 从已有变更/缺陷资料提出候选后确认；不将“回归”解释为仅失败项或自动全量 |
| 其他专项 | 明确指定的移动端、多语言、性能等专项用例 | 仅启用已指定专项；未指定的专项保留范围外，不读全套参考或自动加用例 |
| 指定编号/清单 | 用户明确给出的已有用例编号、已确认清单 | 按清单执行，指明专项编号即代表其进入本轮，不因专项默认关闭而再次排除；未知编号核对输入，不编造 |
| 未指定/泛称全部 | 输入中全部常规功能用例 | 默认排除专项；明确“全部测试，包括专项”则纳入所有输入用例，环境矩阵不清楚仍需确认 |

冒烟或回归候选待确认时可以先做不依赖该选择的分析，但不能执行候选或宣布零项已完成。默认功能范围或已有明确清单无需额外重复确认。

## 选择与组合顺序

1. 读取用户当前明确要求、仍有效的范围确认及输入标签/章节/计划。用户指令优先，不能为迎合标签排除其明确指定编号；矛盾或重要歧义集中确认。
2. 多个并列范围默认取并集，按原编号去重；“仅/只/中的”等限定及模块、平台、显式优先级筛选取交集。用户明确排除的对象不纳入，存在与指定编号的矛盾时确认。
3. 对保留用例展开已确认平台矩阵，按用例×实际环境唯一记录。相同用例同时属于冒烟和功能时不执行两次；不同浏览器/系统是独立检查项。普通业务复核被明确加入兼容矩阵时记录兼容覆盖目的，不改变原文。
4. 输出范围名称、组合方式、选择依据、纳入编号、排除原因和平台矩阵，记录专项启用依据，再进入环境关口。没有标记而无法可靠归类的项列出待确认，不能静默过滤。
5. 范围外清单保留原编号；它不属于未执行、不适用或执行完成率分母。已纳入项缺资源、权限或设备时按未执行处理，产品问题才计阻塞，禁止以事后缩范围隐藏遗留。

## 表达示例

| 用户表达 | 本轮含义 |
| --- | --- |
| 执行冒烟测试和兼容性测试 | 冒烟集合与兼容性集合并集，相同检查项去重；两者各自使用确认的平台范围 |
| 冒烟用例在Chrome、Firefox上测试 | 只取冒烟集合，在两个浏览器环境分别执行，不自动加入全部兼容用例 |
| 执行Android文件分享功能测试 | 文件分享常规功能集合与Android平台筛选，不自动加锁屏/后台专项 |
| 执行功能测试，仅P0/P1 | 常规功能集合与显式优先级条件交集；不能称为冒烟测试 |
| 执行回归测试 | 读取已确认回归范围；缺少时提出候选，不直接只跑历史失败项 |
| 执行全部测试，包括专项 | 全部输入用例，专项已启用；不自行添加输入之外的专项清单 |
| 只执行CASE-001和CASE-009 | 精确清单，即使其中有专项也纳入；操作权限仍由环境关口确认 |

## 混合用例与报告

常规与专项断言混在同一条时保留原编号、原文，明确本轮验证的断言及范围外专项分支；不能把部分范围通过写成原用例全量通过。无法明确拆分时先确认。只缩小平台也需披露实际覆盖，不能外推未运行平台。

报告同时列输入总数、纳入设计用例数、范围外总数及其中专项数、平台检查项和状态数量。范围变更另存确认依据和前后清单，保留之前执行尝试，不改写历史结果。
